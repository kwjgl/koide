# 코이데 기본 서버 · 교회 코드

2026-10-27에 정한 것:

- 교회마다 서버(구글 시트 + `apps-script/Code.js`)를 따로 둔다.
- 카카오 로그인은 기본 서버(이 폴더의 `Code.js`)가 한다. 로그인한 뒤 **교회 코드**를 넣어야 코이데를 쓸 수 있다. 코드가 없으면 공동체도 기도 노트도 쓸 수 없다.
- 교회 코드를 넣으면 그 교회 서버로, 테스트 코드를 넣으면 테스트 서버로 간다.
- 한 번 들어간 사람은 기본 서버가 기억한다. 다시 로그인하거나 휴대폰을 바꿔도 코드를 다시 묻지 않는다.
- 교회 코드 전부터 쓰던 사람은 아무것도 하지 않아도 된다. 이미 로그인된 기기는 그대로 지금 교회 서버로 간다. 새 휴대폰이면 기본 서버가 교회 서버들에 물어서 찾아 준다.
- 앱 관리자 보기(`앱 주소/?appadmin`, 교회 전체 화면 위쪽 링크)에서 교회마다 서버 버전, 오류, 연결 수를 본다. 이름과 기도제목은 오지 않는다.
  - 교회와 테스트 공간을 더하고 고친다. 기본 서버 시트를 열지 않아도 된다.
  - **이 교회로 들어가기**: 앱 관리자는 코드 없이 다른 교회(테스트 공간)로 들어가 본다. 사람 탭은 바꾸지 않아서, 다시 로그인하면 원래 교회로 간다.
  - **첫 관리자 초대 링크**: 그 교회의 전체 관리자 초대 링크(7일, 한 번)를 만든다. 링크에는 교회 코드가 붙어 있어서, 받은 사람은 카카오 로그인 → 교회 확인 → 그 교회의 전체 관리자가 된다.
- 디다코(자매 앱, 성경 공부 노트)도 같은 카카오 로그인·교회 코드를 쓴다(2026-11-05). 교회 탭 맨 끝 칸 `디다코 서버 주소`가 있는 교회만 디다코로 들어올 수 있고, 비어 있으면 디다코에서 그 코드를 넣어도 "아직 쓰지 않아요"가 나온다. 아래 "5. 디다코 노트 서버 더하기"를 본다.

## 설치 순서

`app/config.js`의 `HUB_URL`이 비어 있는 동안에는 예전처럼 움직인다. 아래를 모두 마친 뒤 마지막에 채운다.

### 1. 기본 서버 만들기

1. 새 구글 시트를 만들고 **확장 프로그램 › Apps Script**를 연다.
2. 이 폴더의 `Code.js`를 붙여 넣고 저장한 뒤 `setup`을 한 번 실행한다. 시트에 `교회`, `사람` 탭이 생긴다.
3. **프로젝트 설정 › 스크립트 속성**에 다음을 넣는다.

   | 속성 | 값 |
   |---|---|
   | `KAKAO_REST_KEY` | 지금 교회 서버와 같은 값 |
   | `KAKAO_CLIENT_SECRET` | 지금 교회 서버와 같은 값(쓰고 있다면) |
   | `REDIRECT_URI` | `https://koide.koinobia.com/app/` (디다코도 쓰면 쉼표로 더한다. 5장) |
   | `HUB_SECRET` | 아무도 모르는 긴 글자(40자 이상). 모든 서버에 같은 값을 넣는다 |
   | `APP_ADMINS` | 앱 관리자의 카카오ID(쉼표로 여럿). 처음에는 비워 둔다. 앱 관리자 보기를 열면 "내 카카오ID"가 나오니 그 값을 넣는다 |

4. **배포 › 새 배포 › 웹 앱**으로 배포한다. 실행은 "나", 액세스는 "모든 사용자"로 둔다. 나온 웹 앱 주소를 적어 둔다.

### 2. 지금 교회 서버

1. `apps-script/Code.js`를 새 버전으로 배포한다(서버 버전 `2026-11-13 첫 관리자 초대` 이상).
2. 스크립트 속성에 다음을 넣는다.
   - `HUB_SECRET`: 기본 서버와 같은 값
   - `CHURCH_ID`: 이 교회의 이름표(예: `A`). 기본 서버 `교회` 탭의 이름표와 같게 쓴다
3. 기본 서버 시트의 `교회` 탭에 한 줄을 더한다(앱 관리자 보기의 더하기로 해도 된다).

   | 이름표 | 이름 | 종류 | 코드 | 서버 주소 | 상태 | 메모 | 디다코 서버 주소 |
   |---|---|---|---|---|---|---|---|
   | A | ○○교회 | 교회 | KOIDE24 | 교회 서버 웹 앱 주소 | | | |

   맨 끝 `디다코 서버 주소` 칸은 비워 둬도 된다(5장).

   코드는 쉼표로 여럿 둘 수 있다. 대소문자, 띄어쓰기, `-`는 가리지 않는다. 상태에 `멈춤`이라고 쓰면 그 코드로 새로 들어올 수 없다.

### 3. 테스트 서버(친구, 다른 교회 테스트용)

교회 시트를 복사하지 않는다. 진짜 교인의 이름과 기도제목이 따라가기 때문이다.

1. 새 구글 시트를 만들고 `apps-script/Code.js`를 붙여 넣은 뒤 `sampleData`를 실행하고(지어낸 이름의 예시 부서·소그룹·가정이 들어간다. 빈 채로 두려면 `setup`), 웹 앱으로 배포한다.
2. 스크립트 속성에 다음을 넣는다.
   - `HUB_SECRET`: 같은 값
   - `CHURCH_ID`: `TEST`
   - `AUTO_APPROVE`: `예`. 연결 요청이 승인 없이 바로 연결된다
   - 카카오 속성은 넣지 않아도 된다. 로그인은 기본 서버가 한다
3. 앱 관리자 보기의 **교회·테스트 공간 더하기**로 등록한다(이름표 `TEST`, 종류 테스트, 코드, 서버 주소).
4. 테스트 공간을 꾸릴 사람이 필요하면 그 카드의 **첫 관리자 초대 링크**를 보낸다. 내가 직접 둘러보려면 **이 교회로 들어가기**.

### 4. 앱에서 켜기

`app/config.js`의 `HUB_URL`에 기본 서버 웹 앱 주소를 넣고 올린다.

### 5. 디다코 노트 서버 더하기 (2026-11-05)

디다코 노트도 코이데와 같은 기본 서버로 카카오 로그인을 하고 같은 교회 코드를 쓴다. 카카오 앱은 하나(이름 `코이노비아`)를 코이데·디다코가 함께 쓴다.

1. **카카오 개발자 앱(코이노비아)**: 사이트 도메인과 카카오 로그인 Redirect URI에 `https://didako.koinobia.com/note/`를 더한다(사이트 도메인 칸이 경로를 받지 않으면 `https://didako.koinobia.com`까지만). 코이데 것은 그대로 둔다.
2. **기본 서버 스크립트 속성 `REDIRECT_URI`**: 쉼표로 더한다. `https://koide.koinobia.com/app/,https://didako.koinobia.com/note/` (앞뒤 빈칸은 괜찮다). **첫 주소가 코이데**이고 첫 관리자 초대 링크의 바탕이 된다. 앱이 보낸 주소가 이 목록에 있어야 로그인이 된다(목록이 비어 있으면 검사하지 않는다). 주소에 쉼표가 들어 있으면 안 된다.
3. **기본 서버를 새 버전으로 배포**한다(배포 › 배포 관리 › 수정 › 새 버전). 배포하기 전에 `setup`을 한 번 실행하면 이미 있는 `교회` 탭 첫 줄 끝에 `디다코 서버 주소` 칸 이름이 채워진다(시트를 다시 만들지 않아도 된다. 실행하지 않아도 동작은 하고 첫 줄 이름만 비어 있다).
4. **디다코 노트 서버**(디다코 저장소)의 스크립트 속성 `HUB_SECRET`에 기본 서버와 **같은 값**을 넣는다. 디다코 서버는 확인증의 종류(`typ`)가 `didako-ticket`인 것만 받고, 앱 관리자 보기가 묻는 `appStatus`에는 `{ version, errors }`(서버 버전, 최근 7일 오류 수)만 답한다.
5. **앱 관리자 보기** › 교회 카드 › 고치기에서 `디다코 서버 주소`에 그 교회가 쓸 디다코 서버의 웹 앱 주소(`…/exec`)를 넣는다. 교회가 디다코를 쓰지 않으면 비워 둔다. 앱 관리자 보기의 교회 카드에 디다코 서버 버전과 7일 오류 수가 보인다.

디다코는 요청에 `app: 'didako'`를 실어 보낸다. 없거나 `koide`면 코이데와 똑같이 움직인다.

## 서버끼리 주고받는 것

- **확인증:** 기본 서버가 `{카카오ID, 닉네임, 교회 이름표, 5분}`을 `HUB_SECRET`으로 서명한다. 교회 서버의 `ticketLogin`은 서명, 시간, 이름표(`CHURCH_ID`)를 확인하고 그 서버의 로그인 표시를 내준다.
- **`hubKnows`:** 기본 서버가 모르는 사람이 오면 묻는다. 교회 서버는 "이 카카오ID가 연결됐거나 요청 중인지"만 답한다.
- **`appStatus`:** 앱 관리자 보기가 묻는다. 서버 버전, 부서 수, 연결 수, 승인 기다림 수, 최근 7일 오류 수만 답한다.
- **디다코 확인증:** `app: 'didako'` 요청에는 `{카카오ID, 닉네임, 교회 이름표, 5분}`을 `typ: 'didako-ticket'`으로 서명해 준다. 코이데 교회 서버의 `ticketLogin`은 `typ`가 `ticket`인 것만 받으므로 디다코 확인증은 거절한다(반대도 같다).
- **디다코 서버의 `appStatus`:** 같은 서명(`status|시각`)으로 묻고 `{ version, errors }`만 받아 카드에 보인다.
- 두 요청 모두 5분 안의 서명이 있어야 답한다.
